# kotly.pro — происхождение изображений оборудования

Версия политики: 2026-11-24.

## Обязательные правила

1. **Никакие старые поля `Series.image` не служат подтверждением** внешнего вида оборудования. До явного включения в `src/data/image-manifest.json` они не выводятся в каталоге.
2. Каждая запись манифеста имеет ключ `manufacturerSlug/seriesId`, где `seriesId` — **полное значение `Series.id`** в каталоге данного производителя.
3. Публикуются только `official-model`, `official-series`, `official-generic`; `placeholder` выводится как нейтральная заглушка.
4. Для официальных изображений необходимы локальный файл в `public/catalog/verified/`, официальный URL источника, тип и дата сверки, доказуемое право использования. Статус без подтверждений не проставлять.
5. Не подменять фотографию модели фотографией другого агрегата, даже если оборудование одного типа; `official-generic` обязан сопровождаться точной подписью.
6. Генеративные изображения не допускаются в карточках оборудования. Они могут использоваться лишь как отдельные декоративные изображения страниц, без атрибуции конкретной модели.

## Пример манифеста

```json
{
  "version": 1,
  "updatedAt": "2026-11-24",
  "records": {
    "example-brand/example-series": {
      "status": "official-series",
      "imagePath": "/catalog/verified/example-brand/example-series.webp",
      "sourceUrl": "https://example.com/products/example-series",
      "sourceType": "website",
      "verifiedAt": "2026-11-24",
      "usagePermission": "permission-granted",
      "note": "Пример структуры, НЕ реальное подтверждение"
    }
  }
}
```

**Не копировать этот пример в действующий манифест без проверки.** Разрешение на использование и совпадение с серией необходимо подтвердить редакционно. Дата `verifiedAt` относится к сверке источника, а не к предполагаемой дате изготовления оборудования. Для PDF обязателен `sourcePage`.

## Команды

```bash
npm run check:images
npm run audit:images
node --test scripts/image-audit.test.mjs
```

Отчёт формируется в `reports/images/image-audit.json` и `reports/images/image-inventory.csv`. Его также можно скачать как GitHub Actions artifact `kotly-pro-image-audit` в workflow `Package static kotly.pro for ISPmanager`.

## Ограничения текущего аудита

- Автоматическая инвентаризация обнаруживает статические строковые пути к изображениям в файлах исходных данных. Изображения, присвоенные через динамические функции или константы, не обязательно сопоставляются с конкретным `Series.id`. Это **список на ручную проверку**, а не сертификат происхождения.
- Выявленные повторы одного файла между файлами данных — сигналы для ревизии, а не автоматическое доказательство нарушения.
- Реестр намеренно пуст до документального подтверждения источников и прав. В опубликованных карточках будет заглушка. Это не означает, что сам производитель не публикует фотографию.
- Для новых записей обязательны редакционная проверка и проверка юридического основания использования. Сам по себе официальный URL **не** доказывает разрешение на переиспользование.

## Принцип приёмки

0 изображений в карточках из непроверенных старых `Series.image`, 0 заявлений об официальном происхождении без записи манифеста, 0 отсутствующих файлов среди официально допущенных изображений. Для каждой опубликованной реальной фотографии есть воспроизводимая цепочка доказательств.
