# Подключение доменной почты kotly.pro в ISPmanager

**Назначение:** получать заявки из форм сайта на `info@kotly.pro` через SMTP-сервер, указанный в настройках Thunderbird. В статической публикации React сам не отправляет почту, поэтому ZIP включает серверный PHP-обработчик.

## 1. Предварительные условия

- На хостинге ISPmanager работают **Apache с mod_rewrite и PHP 8.2+** (PHP расширения `mbstring` и `openssl`). Если используется только Nginx без Apache, правила `.htaccess` не действуют: требуется аналогичный location для `/api/v1/leads` с запретом доступа к `/api/v1/_server/`.
- Создан ящик `info@kotly.pro`, известен пароль **ящика** (не от аккаунта REG.RU).
- У домена настроены MX, SPF, DKIM, DMARC для выбранного почтового сервиса; тестируем получение и отправку отдельно.

## 2. Установка сайта

1. Скачать свежий успешный ZIP из workflow `Package static kotly.pro for ISPmanager`.
2. **Содержимое** архива распаковать в **document root** сайта `/www/kotly.pro/` (путь проверить в ISPmanager). В каталоге должны появиться `index.html`, `.htaccess`, `api/v1/leads.php`, `api/v1/_server/vendor/autoload.php`.
3. Удостовериться, что PHP выполняется, а не скачивается как файл. Открытие `/api/v1/_server/notify.php` должно выдавать **403**, но не исходный PHP-код. Для произвольного GET `/api/v1/leads` ожидается **405** (без обработки заявки).
4. Путь почтового конфига вычисляется автоматически относительно реального document root. Если корень `/www/kotly.pro/`, создать каталог `/www/kotly-private/`, вне области выдачи веб-сервера. Выдать владельцу PHP доступ для чтения и записи. Права каталога `700`, файла `600` (с учётом модели запуска PHP). Нельзя класть файл с паролем в `public/`, сайт или GitHub.

## 3. SMTP kotly.pro — подтверждённые настройки Thunderbird

Скопировать содержание `server/php/mail-config.example.php` в **закрытый** `../kotly-private/mail-config.php` и заменить `REPLACE_WITH_PASSWORD_IN_ISPMANAGER_ONLY` на реальный пароль почтового ящика, не отправляя пароль в чат.

Параметры по умолчанию:

- SMTP host: `smtp.kotly.pro`
- SMTP port: `587`
- SMTP encryption: `tls` (STARTTLS)
- SMTP user / From: `info@kotly.pro`
- Получатель: `info@kotly.pro`

Параметры выше сняты с Thunderbird пользователя. Они ещё не доказывают, что SMTP доступен с VPS и имеет валидный TLS-сертификат. Перед боевой отправкой проверить соединение и сертификат `smtp.kotly.pro` через STARTTLS без исключений и без отключения проверки. Предупреждение об исключении сертификата для входящего IMAP `mail.kotly.pro:143` необходимо устранить отдельно.

## 4. Контроль и безопасная повторная отправка

- Пользователь получает номер **только после сохранения заявки**. Статус `sent` означает, что SMTP-сервер принял письмо; не гарантирует попадание во входящие. Статус `pending` означает, что заявка сохранена, но письмо ожидает доставки.
- Заявки сохраняются вне document root в `../kotly-private/leads/`, в JSON-файлах с правами `0600`. Обработчик защищён honeypot, ограничением частоты и повторов по UUID.
- При ошибке SMTP письмо остаётся `pending`. Для повторной отправки назначить cron на PHP CLI, например раз в 5 минут (подставить **реальный** путь к файлу):
  `/usr/bin/php /www/kotly.pro/api/v1/_server/retry.php`
- Ограничить доступ к персональным данным и обеспечить надлежащие сроки хранения/удаления по политике сайта.

## 5. Проверка после публикации

1. Проверить GET `https://kotly.pro/api/v1/leads`: должен быть статус **405**, а не HTML главной страницы.
2. Отправить тестовую заявку через опубликованную форму, согласившись с политикой конфиденциальности. Проверить номер заявки и статус.
3. Убедиться, что письмо появилось в `info@kotly.pro`, включая папку «Спам».
4. Проверить содержание: имя, телефон, email, комментарий, ID серии, URL страницы и дату. Ответ на письмо должен идти на адрес заявителя, если он указан.
5. При отключении SMTP заявка должна остаться в закрытом каталоге и быть доставлена позднее заданием cron.
6. Проверить, что путь `/api/v1/_server/`, данные заявок и пароль недоступны извне.

**Важно:** пока серверный файл с паролем не создан, конечная отправка не работает. ZIP не содержит паролей. Если сайт работает на чистом Nginx или PHP отключён, обработчик не запустится до соответствующей настройки веб-сервера.
